# Delist Lifecycle Invariant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Allow valid owner-authorized delists to pass content validation while retaining lifecycle and publication guarantees.

**Architecture:** Keep the production delist pipeline unchanged. Replace the production-data test's closed list of delisted source IDs with behavioral invariants that apply to every delisted source, then retry issue #290 through the existing owner workflow and verify the deployed catalog excludes Tavernary.

**Tech Stack:** TypeScript, Vitest, Node.js catalog scripts, GitHub Actions.

## Global Constraints

- Preserve source and project records for audit history.
- A delisted source must have `status_reason: "removed"` and `refresh_policy: "paused"`.
- A project backed by a delisted source must not appear in the built public catalog.
- Do not modify unrelated TavernKeeper work in the checkout.
