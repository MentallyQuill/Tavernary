# Tavernary Menu Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Tavernary's Help navigation with a whole-site Menu at `/menu/`, preserve every existing flow, and keep `/help/...` links working as compatibility forwards.

**Architecture:** Canonical route components move under `src/app/menu/` and share a Menu-aware shell. Small client-side compatibility pages remain under `src/app/help/`, replacing only the `/help` pathname segment so query strings, hashes, and GitHub Pages base paths survive. The report subsystem keeps its internal Help names and manifest schema while every new public link and origin uses `/menu/...`.

**Tech Stack:** Next.js 16.3 App Router static export, React 19, TypeScript 6, Vitest, Testing Library, Playwright, GitHub Actions, Markdown, PNG screenshot fixtures.

**Spec:** `docs/superpowers/specs/2026-09-04-menu-page-design.md`

## Global Constraints

- `/menu/` and its seven child routes are canonical.
- Every former `/help/...` route remains a static compatibility page and preserves query strings and hashes.
- Do not restore or reference `/support/`, Ko-fi, or retired support-publishing machinery.
- Do not rename `help-manifest`, `other-help`, `features/help`, `scripts/help`, workflows, or issue labels.
- Public copy names Menu actions directly and keeps staff authority out of visitor-facing pages.
- Historical documents under `docs/superpowers/` remain historical except for this spec and plan.
- The static site must work at both the domain root and a GitHub Pages base path.
