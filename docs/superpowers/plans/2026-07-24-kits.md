# Tavernary Kits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add community-authored Kits to Tavernary’s static catalog, including discovery, inspection, building, GitHub review, withdrawal, reporting, and time-decayed community support.

**Architecture:** Extend the build-time catalog with validated Kit registry records and reaction snapshots, then add a parallel Kits browse mode and a transient right-side workspace to the existing catalog page. GitHub issue forms and Actions remain the only trusted identity and publication boundary; the browser only prepares drafts and manifests.

**Tech Stack:** Node.js 24, Next.js 16, React 19, TypeScript 6, CSS, JSON Schema with Ajv, Vitest, Testing Library, Playwright, GitHub Actions, GitHub REST API

## Global Constraints

- Tavernary remains a static GitHub Pages application with no runtime backend, Tavernary accounts, OAuth, database service, or private authentication.
- A Kit contains a plain-text title of 3–60 characters, a plain-text description of 1–100 words, and an ordered list of canonical project IDs.
- A Kit contains 3–50 unique projects, including at least one Frontend and at least two non-Frontend projects.
- Component order is presentation order only; no Required, Recommended, or Optional roles exist.
- Frontends and purposes are derived from selected projects.
- Every new Kit and author edit requires automated validation and manual repository-maintainer approval.
- A pending edit never changes the published Kit.
- GitHub numeric user ID controls authorship, edits, and withdrawal; login is display-only.
- Drafts exist only in React memory and are lost on refresh or navigation.
- GitHub `+1` reactions are the only support input; Trending uses a 30-day per-vote half-life.
- Removed or quarantined projects remain as disabled Kit rows with unsafe links removed.
- There is no ownership transfer, trusted-user bypass, separate moderation role, star rating, downvote, private Kit, export, bundle, or installation flow.
- Kit text renders as text only; markdown, HTML, and links are rejected.
- Use existing palette tokens and icon conventions; add no dependencies.
- Update pre-alpha contracts in place; do not add legacy compatibility layers.
- Preserve unrelated working-tree changes.

```js
export function countWords(value) {
  const normalized = value.trim();
  return normalized ? normalized.split(/\s+/u).length : 0;
}

export function kitSetKey(projectIds) {
  return [...new Set(projectIds)].sort().join("\n");
}

const markupOrLink = /(?:https?:\/\/|www\.|<[^>]+>|\[[^\]]+\]\([^)]+\))/iu;

export function validateKitDraft(draft, projects) {
  const errors = [];
  const title = draft.title.trim();
  const byId = new Map(projects.map((project) => [project.id, project]));
  const resolved = draft.projectIds.map((id) => byId.get(id));
  const frontendCount = resolved.filter(
    (project) => project?.kind === "frontend",
  ).length;
  const nonFrontendCount = resolved.filter(
    (project) => project && project.kind !== "frontend",
  ).length;

  if (title.length < 3 || title.length > 60) {
    errors.push("Title must contain 3–60 characters.");
  }
  if (countWords(draft.description) < 1 || countWords(draft.description) > 100) {
    errors.push("Description must contain 1–100 words.");
  }
  if (markupOrLink.test(title) || markupOrLink.test(draft.description)) {
    errors.push("Kit text cannot contain links or markup.");
  }
  if (draft.projectIds.length < 3 || draft.projectIds.length > 50) {
    errors.push("A Kit must contain 3–50 projects.");
  }
  if (new Set(draft.projectIds).size !== draft.projectIds.length) {
    errors.push("A Kit cannot contain duplicate projects.");
  }
  if (resolved.some((project) => !project)) {
    errors.push("Every Kit project must exist in the catalog.");
  }
  if (frontendCount < 1 || nonFrontendCount < 2) {
    errors.push("A Kit requires one Frontend and two non-Frontend projects.");
  }
  return { valid: errors.length === 0, errors };
}
```

- [ ] **Step 3: Implement deterministic Trending**

Create `scripts/kits/trending.mjs`:

```js
const DAY_MS = 86_400_000;
const HALF_LIFE_DAYS = 30;

export function effectiveVoteAt(firstReactedAt, publishedAt) {
  return Date.parse(firstReactedAt) < Date.parse(publishedAt)
    ? publishedAt
    : firstReactedAt;
}

export function voteWeight(votedAt, now) {
  const ageDays = Math.max(0, (Date.parse(now) - Date.parse(votedAt)) / DAY_MS);
  return 2 ** (-ageDays / HALF_LIFE_DAYS);
}

export function trendingScore(votes, now) {
  return votes.reduce((sum, votedAt) => sum + voteWeight(votedAt, now), 0);
}
```

```ts
export function selectKits(kits: CatalogKit[], query: KitQuery, search = "") {
  const normalized = search.trim().toLowerCase();
  return kits
    .filter((kit) => !normalized || kit.searchableText.includes(normalized))
    .filter((kit) => matchesAny(query.frontends, kit.frontends.map(({ id }) => id)))
    .filter((kit) => matchesAny(query.purposes, kit.purposes.map(({ id }) => id)))
    .filter((kit) => !query.includesProjectId ||
      kit.components.some(({ projectId }) => projectId === query.includesProjectId))
    .filter((kit) => kit.components.length >= query.minProjects &&
      kit.components.length <= query.maxProjects)
    .filter((kit) => !query.tavernaryPickOnly || kit.tavernaryPick)
    .sort(kitComparator(query.sort));
}
```
