# What is Tavernary?

Tavernary is a map of projects for AI roleplay. It helps you find something
interesting, learn what it does, and follow a link to the creator's own source
page.

![The catalog helps you browse projects](../assets/screenshots/catalog-wide.png)

## Think of it like a library card

A Tavernary project card is like a library card:

- it tells you what the project is about;
- it shows useful clues about the project and its source;
- it points you to where the project really lives.

The card is not the project itself. Tavernary does not copy project files,
host downloads, install extensions, or replace the creator's instructions and
support channel.

## What you can find

The catalog currently groups projects into three kinds:

- **Frontends** are apps or interfaces used to interact with AI roleplay
  systems.
- **Extensions** are add-ons that change or extend a frontend or workflow.
- **System Presets** are reusable settings or prompting resources made by a
  creator.

Tavernary is centered on the SillyTavern community, while also making room for
related roleplay frontends when the catalog has enough information to describe
them clearly.

## Where Tavernary gets its information

Cards can include creator-written details, facts observed from a public source,
and helpful explanations from Tavernary tools. These pieces can have different
ages. A card marked **Pending enrichment** is waiting for a verified fact; it
does not mean the fact is zero or missing forever.

Tavernary Companion is a connected extension manager for SillyTavern. It can
help with the extension-management part of the journey, but Tavernary and
Companion do not own the projects listed here.

## What inclusion means

Being listed is not an award, safety certificate, or promise that a project is
still maintained. Before using a project, open its source page and read its
instructions, license, release history, and support information.

## Why safety information needs context

TavernKeeper uses a bundle of deterministic open-source security tools to look
for evidence, then uses contextual review to help explain the hits. A raw scan
can notice something in a test or build script that looks alarming but is not
the same as a dangerous action for a player.

That is why a scan result is advisory evidence, not a traffic-light verdict.
Warning colors should stay meaningful. A yellow label on every small issue
would teach people to ignore yellow, including when a project really needs a
closer look.

## What Tavernary is not

Tavernary is not a file host, code host, marketplace, publishing platform,
blog, forum, or social network. It does not decide which projects are “good,”
and it does not provide support for software made by other people.

For the project direction behind these boundaries, see
[Bounding the Problem in the main README](../../README.md#bounding-the-problem).
